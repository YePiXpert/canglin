# 数值精度决策与差异报告

本次不批量转换既有 SQLite Float，也不改变现有金额报表的历史语义。后续迁移目标：数量最多 6 位小数、单价最多 4 位小数、金额 2 位；十进制运算，每行采用 ROUND_HALF_UP，再把行金额相加。先确定货币与舍入约定，再选择定点整数或十进制字符串存储，禁止直接依赖 JavaScript 二进制浮点舍入。

差异审计脚本 `scripts/precision-audit.py`（只读报告旧台账 `Item` 表 Float 数量、单价的精度裁剪与金额舍入差异）已于 2026-10-08 随旧台账一并停用并删除：旧台账数据按重构要求视为测试数据，迁移时直接删除、不做转换，不再有需要审计的 Float 账目。停用时本文记录的历史差异报告状态仍为「待数据输入」。新业务表按上述约定以定点整数存储，数量、单价、金额分别为放大 10⁶、10⁴、10² 倍的整数（`*Units` 字段）；十进制解析、格式化与 ROUND_HALF_UP 舍入见 `packages/shared/src/decimal.ts`。
