# 人工录入：没有 OA 单号，部门与人员少打字（2026-10）

2026-10-16 用户反馈：

1. 人工录入时有时没有 OA 单号——打个招呼就采购了；
2. 手输内容繁琐，比如部门、人员。

2026-10-26 补充：人工录入与修改申请信息的部门、经办人输入框明确显示「输入新部门或选择已有部门」「输入新姓名或选择已有人员」，提示保存后会加入候选。直接填写即可使用，无需先维护名单；经办人是申请记录中的姓名，不会创建登录账号。浏览器流程覆盖填写全新部门、经办人并确认后进入候选清单。

## 1. 现状与根因

| 问题 | 根因 |
|---|---|
| 没有 OA 单号录不进去 | 人工录入的「OA 流水号」必填（`workflowRequestCreateSchema.serialNumber` 至少 1 个字），弹窗说明写「填写已经通过 OA 审批的申请」。没有单号只能编一个（「无」「口头」），几张申请同一个号分不清；申请入账后流水号改不了（没有修改接口），OA 单补下来也填不回去，再导入补办的 OA 单就多出一张重复的申请。系统也不查流水号重复：同一张 OA 单导入一次、再人工录一次，两张都能入账。 |
| 部门、经办人每次手打 | 人工录入的「申请部门」「经办人」是空白输入框，没有候选。部门名常常很长（致远单上的「行政管理部（党委办公室）」11 个字）。`Input` 早有 `suggestions`（datalist，注释写着「如历史领用人、部门」），但哪里都没接上。 |
| 发放时领用人一行一行打 | 直接发放 / 库存领用的领用人按行必填：一张申请 5 样东西发给同一个人要打 5 遍，也没有候选。领用部门只在从申请详情打开时带上申请部门。 |
| 写法不一会拆散报表 | 报表「按部门」按申请部门分组，「领用按人」按 领用人 + 部门 + 物品 分组；「综合部」和「综合管理部」、半角和全角括号、多一个空格，都会变成两行。 |
| 明细从头打 | 导入草稿已经按物品库填单位（上一轮的 U1），人工录入的品名、规格、单位还是空白框，没有物品库候选。 |
| 打错了改不了 | 申请的流水号、部门、经办人、申请日期、备注入账后不能改；只有还没有业务记录的申请能删了重录。 |

## 2. 方案

### 2.1 没有 OA 单号（N）

- **N1 勾选「没有 OA 单号」**：人工录入的「OA 流水号」旁边一个复选框「没有 OA 单号」（用户 2026-10-16 选定：勾了才能空着，防止手里有单号却忘了填）。勾上后流水号框变成只读，占位写编号的样子「无OA-20261016-…」，框下小字「保存时自动编号；OA 单补下来后可以在申请详情补填」；取消勾选恢复刚才填的号；没勾时照旧必填。弹窗说明改为「OA 审批单，或打过招呼、还没有 OA 单号的采购，都在这里录；采购和到货之后分别登记」；空态里的「人工录入一张已审批申请」改成「人工录入一张申请」。导入不变：OA 原件都有流水号，确认入账照旧要求填。录入契约多一个 `autoSerial`：为 true 时流水号必须空着，为 false 时必须填。
- **N2 自动编号**：勾了「没有 OA 单号」时由服务端编号，形如 `无OA-20261016-01`：申请日期 + 这一天第几张没有 OA 单号的申请（两位，超过 99 自然变三位）。在写入事务里取这一天已用的最大序号加一；同一个操作编号重复提交，返回同一张申请。编号本身说明了来历，列表、面包屑、来源提示、审计和 AI 回答里都不用另加标注。
- **N3 系统编号留底**：`ProcurementRequest.systemSerial`（可空、唯一，迁移 `20261016000000_request_system_serial`）记下系统编的号，以后补填了 OA 流水号也不变：按旧编号照样搜得到（纸质小票上记的是旧号也能找到），序号也不会重复发出去（删掉的申请除外，它没有任何业务记录）。申请视图带 `systemSerial` 与 `autoSerial`（流水号就是系统编号，即还没有 OA 单号）。手填的流水号即使写成「无OA-…」也当 OA 流水号，序号会避开它。AI 助手查询申请的工具说明补一句「`无OA-` 开头的是没有 OA 单号的申请」。
- **N4 补填 OA 流水号**：申请详情说明行写「人工录入，没有 OA 单号（补填）」，「补填」打开「修改申请信息」：已经取消勾选「没有 OA 单号」并聚焦流水号（这个初始状态不算改动，关掉不会追问）。补填后显示「人工录入 · 系统编号 无OA-20261016-01」。补办的 OA 单可以在「OA 原件与附件」上传（原来就能传）。
- **N5 修改申请信息**：申请详情「…」菜单加「修改申请信息」（在「删除申请」上面）：流水号与「没有 OA 单号」、申请日期、申请部门、经办人、申请备注，与人工录入同一套单据头和候选（P2）。所有申请都能改，包括导入的和已有业务记录的：这几项只是申请的描述，不牵涉数量与金额；改了部门，报表「按部门」跟着变，就是在纠错。接口 `PATCH /workflow/requests/:id`，审计「修改申请信息」按 `{ 字段: [旧值, 新值] }` 记改了的几项（审计页显示成「申领部门：综合部 → 综合管理部」）；什么都没改时保存直接关闭，不调接口（服务端也不写库、不留审计）。手填的流水号不能是系统给别的申请编过的号（409）。申请日期不能改到这张申请第一次（未撤销的）采购或取消之后（409，消息写出那一天）：先采购后补单时，补办 OA 单不用改申请日期，弹窗里写明；系统编号里的日期不跟着改。补填就是取消勾选、填上 OA 流水号；反过来勾上「没有 OA 单号」，流水号换回这张申请的系统编号（以前没有就新编一个），用来纠正以前随便编的号（「无」「口头」）。明细（品名、数量、单位）不在这里改。导入的申请改过之后又「撤回入账」，导入草稿仍是入账时的内容。
- **N6 流水号重复提醒**：人工录入、修改申请信息与导入草稿里，流水号与已有申请相同时，框下一行琥珀色「已有申请用了这个流水号：部门 · 经办人 · N 条明细 · 查看」，不拦保存（极少数情况一张 OA 单确实要分两张录）。查询参数 `serial`（精确匹配）。
- **N7 导入时提醒可能是补办的单**：导入草稿的经办人和某张还没补填流水号的申请相同时（不论是否办结：先采购后补单，补办时多半已经办完；只按经办人对，按部门对太宽），草稿上方琥珀色提示，最多列 3 张：「张三还有 1 张没有 OA 单号的申请（无OA-20261016-01 · 签字笔等 3 项）。如果这份 OA 单是给它补办的，打开那张申请补填流水号、上传这份原件，再「放弃草稿」，免得重复入账。」带链接，不拦入账。查询参数 `autoSerial=1`；任务没入账时取，换任务、撤回入账、回到这个标签页（可能刚在别的标签页补填过）时重新取。

### 2.2 部门与人员（P）

- **P1 候选从历史汇总，不用维护名单**：新接口 `GET /workflow/directory` 汇总已有申请的 部门 / 经办人 与未撤销发放单的 领用部门 / 领用人，给出部门列表、「人员 + 部门」列表和最近录入的 4 组「部门 · 经办人」，按最近一次使用排、其次按次数。数据小、只有本系统会写：弹窗（人工录入、修改申请信息、发放）与导入草稿每次打开取一次最新的，不做缓存（`useDirectory`）；取不到就没有候选，照常手填。
- **P2 下拉选择框（用户 2026-10-16 追问「部门和经办人除了手填能否在已有的选择」）**：部门、经办人不用浏览器自带的输入建议（要先打字才出现，看不出能选），改成新组件 `Combobox`：框右边有下拉箭头，点框或箭头就展开用过的写法（最近用的在前），打字按包含的文字筛，没有的照样手填。下拉第一行是「照打的字」（标「新的」，和已有的一模一样时不出现），所以打完字直接回车不会被换成别的；方向键往下才是已有的选项。人员一行右边小字写部门。
- **P2a 人工录入与修改申请信息的部门、经办人**：
  - 申请部门：下拉是用过的部门；经办人：下拉是用过的人，已填部门时这个部门的人排在前面。
  - 经办人选中（或打全了）一个以前出现过的人、部门还空着时，自动填他最近一次的部门，框下小字「按以往记录」；改了部门小字就消失，之后不再自动改。
  - 头部下面一行「最近」药丸：最近 4 组「部门 · 经办人」，点一下两项都填上；两项都填了就不显示。
- **P3 发放（直接发放 / 库存领用）**：
  - 弹窗头部加「领用人」（与业务日期、领用部门同一行）：填一次，各行跟着填；某一行单独改过就不再跟着变；「拆给另一位领用人」拆出的行空着，要另填。
  - 从申请详情直接发放时，「领用人」默认填这张申请的经办人，框下小字「默认是申请的经办人，可以改」（用户 2026-10-16 选定）。库存领用不预填。
  - 领用部门、领用人（头部和每一行）都是 `Combobox` 下拉；选了以前的领用人、领用部门还空着时，自动填他最近一次的部门。
- **P4 写法相近提示**：部门、经办人、领用人填的值不在历史里，但去掉空格、统一全角半角与括号后和已有的某一个相同（部门另认「是某个已有名称的开头，且只对应一个」）时，框下一行「是不是「行政管理部（党委办公室）」？」，点了替换。不拦保存。人名不做「开头」匹配，免得把「张三」提示成「张三丰」。
- **P5 人工录入的明细用物品库**：品名格是 `Combobox`，下拉是物品库品名（右边小字写单位）；规格格下拉是这个品名用过的规格；单位与导入草稿同一规则：同名同规格只有一个单位、或同名只有一个单位时直接填，小字「沿用物品库」，人工改过就不再动；下拉给物品库单位、规格里的包装层级与常用单位。导入草稿里这段逻辑抽成共用函数。
- **P6 导入草稿的单据头**：部门、经办人框换成同样的 `Combobox` 下拉，加 P4 提示；识别出来的值不自动改。

## 3. 不做的事

- 不做要维护的人员名单 / 通讯录：候选全部来自已有记录，录过一次下次就有。以后写法乱了、需要批量改名或合并，再在设置里加「部门与人员」。
- 不做拼音首字母搜索：下拉按包含的文字筛，输入法打一两个字就能筛出来。
- 不把补办的 OA 导入合并进已有申请：两边明细可能对不上，自动合并容易错；按 N4、N7 补填流水号并上传原件。
- 不在「修改申请信息」里改明细：数量与单位已经牵涉采购和库存；明细错了照旧删除重录（没有业务记录时）或「取消未采购量」。
- 不在工作台单列「待补 OA 单」：搜索框搜「无OA」就能列出全部。

## 6. 实施记录

2026-10-16 实施 N1–N7、P1–P6。

**实施中的调整**

- P2：用户追问「部门和经办人除了手填能否在已有的选择」后，下拉从浏览器自带的 datalist（要先打字才出现）换成新组件 `Combobox`（reka-ui 的 Combobox）。reka 在打字时会自动高亮第一行、回车选中它，所以下拉第一行固定是「照打的字」（标「新的」），回车留下打的字；点框或箭头展开时列出全部，打字才筛。reka 在选中、外部改值后会把同一个值再发一遍，这种回传不算打字（否则下次点开只列出当前值）。
- N5：审计按 `{ 字段: [旧值, 新值] }` 记，和审计页已有的「改了什么」写法一致，显示成「申领部门：综合部 → 综合管理部」；什么都没改时保存直接关闭，不调接口。另加一条保护：手填的流水号不能是系统给别的申请编过的号（否则两张申请显示同一个号，返回 409）。
- N7：只按经办人对、不论是否办结（先采购后补单，补办时多半已经办完；按部门对太宽，一个部门可能有很多张），最多列 3 张。
- P1：候选不缓存，弹窗与导入草稿每次打开取一次（数据小，只有本系统会写，缓存要在各处写入后失效，容易漏）。
- P5：规格不自动填（规格是区分物品的一部分，填错了会建出不同的物品），只给下拉；单位照导入草稿的规则自动填。
- 文案：勾选后流水号框的占位原来是「保存时自动编号：无OA-…」，在桌面 1.2 份宽的格子里被截断，改成只写编号的样子「无OA-20261016-…」，说明放到框下；发放弹窗的提示用「默认是申请的经办人，可以改」，不写「他」。
- 单测环境加 `apps/web/src/test-setup.ts`：jsdom 没有 `scrollIntoView` 与 `ResizeObserver`，reka 下拉展开时要用。
- 浏览器测试：导入页两条用例按 `textbox` 角色找「申领部门」，改成 `combobox`；直接发放的公共步骤加一句断言「领用人默认是经办人」。
