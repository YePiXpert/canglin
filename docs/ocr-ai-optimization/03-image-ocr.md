# 03 截图与照片的本地 OCR 路径

目标：AI 未启用或失败时，PaddleOCR 结果的行列重建更稳，并用置信度、金额交叉校验和数字归一减少人工核对盲区。本批 13 份原件都是文本层 PDF，这条路径没有真实样本，改动以单元测试与合成夹具为主，Paddle 参数调整必须经真实容器验证。

## 1. 噪音与单据头

- 01 第 5 节的噪音清单和第 4 节的标签放宽同样作用于 `rebuild_from_entries` 与 `rebuild_from_lines`。
- OCR 行的单据头改用"标签词右侧同一行"规则（01 第 4 节）替代全文正则优先：`_positioned_rows` 已有行分组，标签与值在同一行时直接取右侧单元格；多行部门名按行距 0.3 倍行高内合并。

## 2. 列归属（`_header_columns`、`rebuild_from_entries`）

- 列区间：表头各词的 `[left, right]` 向两侧扩展到与相邻表头的中点，第一列向左、最后一列向右扩展到页边；单元格按与各列区间的水平重叠比例归列，跨两列时取重叠大的一侧。替代现在"距表头中心最近"的规则，解决左对齐长品名串入规格列。
- 两行表头：相邻两行都只含表头关键字且 x 范围重叠时合并为一行，键取两行文字拼接后的匹配（"规格"+"型号"仍是 spec，"生产"+"厂家"是 brand）。
- 列键表与字段映射复用 01 第 3 节（备注列解释、`amount`、`spec` 合并、`(单位：X)`）。
- 续行：现有规则（只含 name 或 spec 且行距不超过 0.3 倍行高）扩展为"没有序号整数且没有数量数字"的行并入上一行，与 01 第 2 节第 8 条一致；但 OCR 行距容差放宽到 0.5 倍行高。
- 表格结束：遇到"插入项""合计""总金额"或审批标签行时关闭列定义。

## 3. 数字归一（只在数量、单价、金额单元格）

- 字符替换：`O`、`o` 为 `0`；`l`、`I`、`|` 为 `1`；`。`与`，`在数字之间分别为 `.` 与千分位；全角数字转半角；去掉千分位分隔与前后"元""¥"。
- 替换后仍不是数字则留 null 并警告，不做模糊匹配。品名、规格列不做任何替换。

## 4. 置信度告警

- 行最低置信度低于 0.6：警告"第 N 行识别置信度低，请对照原件"。
- 数量或单价单元格置信度低于 0.8：警告"第 N 行数量（或单价）置信度低"。
- 阈值作为常量，评测后可调。前端用现有 `source.confidence` 对低置信度行加底色。

## 5. 金额交叉校验

同 01 第 3 节：数量、单价、金额齐全而乘积与金额差超过 0.01 时警告，不改任何值。

## 6. Paddle 参数与照片预处理（需真实容器验证）

- `text_det_limit_side_len=2560`、`text_det_limit_type='max'`，与输入缩放一致，避免检测阶段再缩小密表小字。
- `text_rec_score_thresh` 保持默认，低分不过滤，交给置信度告警。
- 照片（JPEG 原件或含 EXIF）在 OCR 前：`exif_transpose`、转灰度、`ImageOps.autocontrast(cutoff=1)`；截图不处理。
- `use_doc_unwarping` 只对照片评估开启：在 2 CPU、4GB 的 `canglin-ocr:test` 容器里跑 `tests.smoke_engine` 与若干照片样本，内存峰值超过 3GB 或单页超过 60 秒则不开启。`enable_mkldnn` 按 [升级说明](../upgrade-2026-09.md) 保持关闭。
- PP-StructureV3 表格识别与基于 OpenCV 的图像网格检测不在本轮范围：前者模型与内存开销超出当前资源，后者依赖只在 Paddle 环境可用。

## 7. 代码改动

| 文件 | 改动 |
| --- | --- |
| `apps/ocr/app/reconstruct.py` | 列区间与重叠归列、两行表头、续行规则、表格结束、置信度告警、交叉校验 |
| `apps/ocr/app/normalize.py` | 数字归一函数、备注单位解释（与 01 共用） |
| `apps/ocr/app/ocr.py` | 检测参数、照片预处理开关 `OCR_PHOTO_PREPROCESS`（默认 `1`） |
| `apps/ocr/app/main.py` | `/parse` 对 `.jpg/.jpeg` 走照片预处理 |
| `apps/web` | 低置信度行底色 |

## 8. 测试

- `test_reconstruct.py`、`test_geometry.py`：合成 entries 夹具覆盖左对齐长品名、跨列单元格、两行表头、换行续行、"合计"关闭表格、备注单位、金额不符、低置信度警告、数字归一。
- `test_api.py`：带 EXIF 的 JPEG 经预处理后仍返回 `IMAGE_OCR`，坐标仍按原图归一化。
- 真实容器：`docker run --rm --network none --cpus 2 --memory 4g canglin-ocr:test` 与 `python -m tests.smoke_engine`，记录内存峰值与耗时。

## 9. 验收

- 合成夹具全部通过；现有 OCR 轻量套件不回归。
- 真实容器冒烟通过，参数调整的内存与耗时记录在发布记录。
