# 界面文字审查（2026-10）

2026-10-16 用户看到申请单的筛选「全部 · 有待采购 · 有待到货 · 有待处理 · 已办结」，问「有XXX 这种描述是不是不对劲」，要求对照本机已部署的实例确认全部描述文字。

## 1. 怎么查的

- **本机部署的实例**（`77d4a2d`）：用户给了管理员密码，登录后只读走查了 26 个页面与弹窗（工作台、申请单与 7 张申请的详情、修改申请信息与人工录入弹窗、导入页与已入账任务、库存四个页签、报表、设置各区、供应商、审计日志、AI 助手、404、登录页），只打开、截图、读文字，没点任何保存或确认。数据库没有直接读：页面上已经能看到全部数据。
- **代码里的全部界面文字**：前端 83 个文件约 1300 行（含空态、报错、提示、弹窗的各种状态、读屏标签），以及服务端会显示到页面上的报错。库存 / 报表 / 外壳这一块由一个只读代理审过；其余几块的代理因为额度用完中途停了，由我按同样的标准逐段审完。
- 标准：撞固定词或语序别扭；和实际行为不符或过时；同一个东西叫法不一致；开发词、会计行话；标点与格式。

## 2. 改了什么

### 2.1 「有待」撞词

「有待」本身是个词（有待提高、有待确认），「有待采购」读起来像「尚待采购」。

| 位置 | 原来 | 现在 |
|---|---|---|
| 申请单的进度筛选（工作台待办同一组件） | 全部 · 有待采购 · 有待到货 · 有待处理 · 已办结 | 全部 · 待采购 · 待到货 · 到货待处理 · 已办结（「待处理」单独放看不出是什么，写全） |
| 申请详情「申请明细与数量进度」的说明 | 申请量不变；同一条明细可以同时有待采购、待到货、待处理和已处理的数量 | 申请数量不变；同一条明细可以一部分待采购、一部分待到货、一部分待处理或已处理 |
| AI 助手的示例问题 | 哪些申请还有待采购的数量？ | 哪些申请还没采购完？ |

### 2.2 同一个东西叫法统一

| 概念 | 原来的几种叫法 | 统一成 |
|---|---|---|
| 申请的部门 | 人工录入、详情叫「申请部门」，导入草稿叫「申领部门」 | 申请部门 |
| 取消还没采购的数量 | 按钮「取消未采购量」、弹窗「取消未采购申请量」、记录类型与审计「申请余量取消」 | 取消未采购量 |
| 取消还没到货的采购 | 按钮「取消未到货量」、弹窗「取消未到货采购」、记录类型与审计「采购取消」 | 取消未到货量（报表里的金额类别「采购取消」不变） |
| 退回供应商 | 按钮「退回供应商」、弹窗与审计「供应商退货」、卡片与报表「实物退货」 | 动作、弹窗、审计都叫「退回供应商」；记录类型仍叫「供应商退货」；报表「供应商退货金额」，卡片金额写「退货金额」 |
| 盘点调整 | 按钮「盘点调整」、记录类型与审计「库存盘点」、来源「盘点 / 补录」 | 盘点调整 |
| 撤销 | 「撤销登记 / 已撤销」，弹窗「撤销业务登记」、说明「回冲」、流水「冲销」、报表「作废」 | 撤销 |
| 直接发放 | 句子与标签里常写「直发」 | 句子、标签写「直接发放」；进度表的窄列表头仍叫「直发」 |
| 识别 | 「识别」「解析」混用 | 识别 |
| 到货 | 报错里叫「收货」 | 到货 |
| 导入页 | 导航「导入单据」、顶栏「导入 OA 单」、页头「导入 OA 单据」 | 导入 OA 单 |
| 报表页 | 导航「报表」、页头「统计报表」 | 报表 |
| 供应商页 | 设置导航「供应商与比价」、页头「供应商与成交价格」 | 供应商与成交价；设置分组「主数据与记录」改「供应商与日志」 |
| 修改付款与发票 | 审计「修改单据信息」 | 修改付款与发票 |
| 来源行 | 同一张卡上「来源 #」「来源明细 #」并存；库存来源同一行写成「来源明细 #21 · 到货明细 #21」 | 「来源明细 #」；到货来的批次只写「到货明细 #N」 |

### 2.3 和实际行为不符、过时

| 位置 | 原来 | 现在 |
|---|---|---|
| 申请单的进度标签 | 单条明细的申请写「待采购 1 项」，详情页写数量 | 单条写数量，多条写项数（和详情一致） |
| 新增库存物品弹窗、库存空态 | 申请到货入库会自动建立物品 | 录入或导入申请时就建立物品；本来就有的库存先新增物品，再用「盘点调整」录入数量 |
| 库存「全部物品」里没入过库的物品 | 还没有来源批次：新增的物品要先用盘点调整录入数量 | 还没入过库：申请里的物品登记到货后才有批次；本来就有的库存用「盘点调整」录入（原文会让人对申请带进来的物品做盘点，凭空多出库存） |
| 库存「现在没有库存」的说明 | 到货后登记入库的物品才算库存…申请带进来还没入库的 | 这里只列当前库存大于 0 的物品（盘点、归还也会让库存大于 0）…还没到货或还没入库的、已经用完的 |
| 库存流水的空态 | 登记入库、库存领用、退货和盘点调整之后… | 登记到货、入库、发放、归还、退回供应商和盘点调整后…（第一笔流水来自到货） |
| 库存「领用与归还」页签 | 面板标题是「业务记录」 | 标题与页签同名，说明默认列领用发放、其余换类型查看 |
| 报表页头 | 采购、退款和领用均按实际业务日期统计；作废单据已排除 | 采购、到货、退货和领用都按登记的业务日期统计；已撤销的登记不计入 |
| 报表「采购单数」的说明 | 按部门分组时「跨部门单据各计一次」（读成「每张只算一次」，意思正相反）；不分部门时「期间内的采购成交单」 | 跨部门的采购单，每个部门各算一单；这段时间的采购单 |
| 报表「员工领用」空态 | 员工归还单独列明 | 员工归还记在「归还数量」一列 |
| 导入成功 | 已创建 N 条，合并 0 条，跳过 0 条 | 已创建申请：N 条明细，关联 N 份原件（合并、跳过在新流程里永远是 0） |
| 导入页的 AI 说明 | 启用自动智能导入后… | 开启「上传后自动识别单据」后…（与设置里的开关同名） |
| 人工录入 | 按原件逐行填写 | 逐行填写（没有 OA 单号的申请没有原件） |
| 登记采购时链接下的说明 | 来自申请（OA 原件上的链接）——手动给申请加的链接也显示这句 | 来自申请 |
| 登录页 | 输入初始化时生成的恢复码；导入已审批的申请 | 输入恢复码和新密码；导入或录入申请 |
| AI 助手未启用 | 在系统设置选择 Gemini、GPT 或 Grok | 在系统设置里连接 AI 服务并启用（模型列表可配置） |
| 审计日志 | 放弃草稿显示成英文代码 `IMPORT_DISCARD`；「对象」列是 `system`、`workflow`、`procurementRequest #7` | 「放弃草稿」；对象写「系统 / 业务登记 / 申请 #7 …」 |
| 审计日志的操作类型筛选 | 列着旧台账等十几种已经不会再记的动作 | 只列现在会记的动作（旧动作名保留，只用来显示以前的记录）；「传附件 / 删附件 / 删备份」写全 |

### 2.4 开发词、行话与读不顺

库存流水「带符号数量…冲销」「业务 #」；撤销「回冲本次数量」「检查依赖」；查看业务来源「按稳定的业务明细逐层查看」；库存领用来源「按实际数量自动关联入库来源」；卡片「冲减成交」；导入「识别置信度低」「无可信文本来源」「人工录入／历史结果」；设置「会话」「已过账」「容器」「保留最近 N 份」；登录「连接不上后端服务…容器没跑起来」「密码遗忘」「登 录」「数据自持」；错误页「错误已记录在浏览器控制台」；表头「可操作」「尚欠」；报表「最早 至 最新」（改为「全部时间」，只填一头写「…起」「截至 …」）、「换货保留成交金额」；AI 回答下面的查询名 `query_requests` 等。都换成白话。

### 2.5 服务端报错

「超过净申请需求」「超过采购剩余数量」「后续库存动作」「来源单据日期」「收货」「该来源或操作已经使用」「已撤销单据不可修改」「存在后续业务」「会话已过期 / 已失效」「请配置并检测智能导入能力」「单据解析失败」「违反唯一约束」改成说人话的说法，并和按钮叫法一致。

## 3. 顺带修的功能问题

- **用恢复码重置密码后，新恢复码丢了**：服务端重置密码时会把恢复码换新（用过的作废），但没把新码返回，页面也没提，管理员手里的旧码已经失效却不知道，下次忘记密码就没有可用的恢复码。现在接口返回新恢复码，登录页像初始化时一样显示一次、可复制，确认保存后回到登录。

## 4. 发现了但没改

- **审计日志的「来源 IP」一直是 nginx 容器的地址**（生产上全是 `172.22.0.4`）：服务端没从反向代理的转发头里取到真实地址。要查 `trustProxy` 在当前部署下为什么没生效，另做。
- **生产上没有应用内备份**，自动备份也没开（升级脚本的回退点在部署目录里，但设置页「备份管理」是空的）：建议在设置里开自动备份。
- **生产数据的品名里有商城页面的杂字**：如「得力 7084 铅笔 2B 12支/盒 （单位：盒） 墨绿 没有阶梯价和同款商品时增加高度」「…单位:盒」「(白色)」，规格也都塞在品名里。这些申请都还没有业务记录，可以在导入页「撤回入账」、改好再入账；要不要清理由用户决定。
- 手机底栏「申请」的读屏全称（「申请单」）：有一条手机端测试按「申请」找这个链接，没顺手改。
- 报表的「期间」、库存「显示更多（共 N 种）」重复写总数、筛选用词的个别「可能」项：属于偏好，没改。
