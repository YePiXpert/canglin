# 仓廪 1.0.0-beta.1 交付与验收

日期：2026-10-23。交付版本 `1.0.0-beta.1`，Git tag `v1.0.0-beta.1`。本版在 `0813b985ff930a782dea0c6b7c76807dfdf3489f` 基础上整合付款与开票工作台、恢复码验证、OCR 改进，以及库存盘点、补货与采购跟进。按本次交付要求采用新的 1.0 系列编号，历史 v2.x 标签保留；以明确的 tag / 提交和镜像摘要选择版本。

## 使用入口

| 入口 | 本版能力 |
| --- | --- |
| 库存与领用 → 库存盘点 | 创建多物品草稿，区分未盘与实盘0；差异筛选、原因、期间流水、明确重盘；整单记账、撤销、打印与 CSV |
| 库存与领用 → 库存补货 | 安全库存/目标/采购倍数、批量规则、补货来源解释、低库存与已安排筛选；建立、编辑、放弃草稿或生成正式申请 |
| 工作台 → 采购跟进 | 到货明细与采购发票跟进；预计日期、下次日期、追加记录、批量改期、停止/恢复；到期、逾期、未设计划及历史筛选 |
| 申请详情 | 库存补货用途、当前跟进计划、来源与处理入口 |
| 报表 → 付款与开票 | 跨申请的采购单清单、独立付款/开票/附件筛选、批量状态修改与 CSV |

盘点只清点已入库数量。任何库存流水（包括撤销）都会改变物品库存版本；过期盘点整单不记账，须明确重盘发生变化的物品。盘盈、盘亏共用现有来源追溯、非负余额和撤销规则。无差异完成不产生零流水。

补货建议使用精确整数定点运算：目标减现有库存、库存补货申请待采购量、在途量、到货待入库量、其他有效草稿；有采购倍数时向上取整。普通部门采购不抵扣库存补货供应。补货采购→到货→入库在互斥阶段间迁移；直发退出补货供应。草稿本身不写库存，确认时才生成一张 `STOCK_REPLENISHMENT` 申请，之后走原有业务流程。

跟进完成状态从业务事实计算。到齐或取消剩余量完成到货跟进；已开票且有发票附件完成发票跟进。换货、撤销到货或删除最后一份发票会重新出现，旧计划与日志保留。停止跟进不会改变收货或开票事实；提醒仅在站内显示，不发送邮件或消息。

所有新增写接口使用登录认证、幂等回执和同事务审计；草稿、规则及跟进使用预期版本保护，批量冲突整批回滚。实际 API 见[实施方案第5节](inventory-planning-2026-10.md#52-实际接口分组统一-apiplanning-前缀)。

## 迁移与回退

新增迁移 `20261023000000_inventory_planning`：

- 为物品增加 `stockVersion=0`；所有 STOCK 流水及回冲在同一事务递增版本。
- 旧申请用途默认为 `GENERAL`，不猜测是否补货；物品默认未启用补货规则。
- 新增盘点、补货规则/草稿、跟进计划/日志七张表，保留旧数据、索引、外键与 CHECK。新表约束状态、数量、版本和跟进目标二选一。
- 新记录、关联、版本和幂等回执均随全库备份恢复；恢复后旧会话失效。

升级前先停写并保存完整数据库、附件、密钥与旧镜像的回退点。新旧应用不能同时写同一数据库：旧应用不会维护库存版本。回退时恢复升级前的数据与旧镜像，不能仅换回旧容器；回退会丢弃备份之后的业务变动。使用现有 `deploy/upgrade.sh` / `deploy/rollback.sh` 的完整回退流程。

Beta 标签构建不会自动成为镜像 `latest`；`latest` 仅由主分支明确发布。推送、打 tag 和发布镜像不触发生产部署。

## 发布与隔离试用

发布流程为：本地检查 → 推送开发分支 → 该提交远端 CI → annotated tag → 标签 CI / 镜像 → GitHub prerelease。三个镜像绑定同一提交，Release 附件 `trial-candidate.env` 固定完整提交及三个不可变摘要。远端运行结果以 Release 链接为准，不在源码里预填尚未产生的构建编号。

仓库 `deploy/trial-candidate.env` 保留上一轮 `0813b98` 候选，Beta 试用应明确选择 Release 附件，避免把源码内的旧候选误当成本版：

```sh
gh release download v1.0.0-beta.1 --repo YePiXpert/canglin \
  --pattern trial-candidate.env --dir /tmp/canglin-beta-trial
export CANGLIN_TRIAL_CANDIDATE=/tmp/canglin-beta-trial/trial-candidate.env
bash deploy/trial.sh up
bash deploy/trial.sh check
bash deploy/trial.sh smoke
bash deploy/trial.sh stop
```

试用使用独立项目、端口、密钥和数据卷；`stop` 保留试用卷。执行前确保本地仓库能解析本版 tag（`git fetch --tags`）。生产升级需要单独执行明确版本的部署流程。
